Workload

What will the model do? Simple tasks (classification, extraction) can use small cheap models. Complex tasks (reasoning, coding, agents) need higher-tier models with better instruction-following.
How fast does the user need a response? Async workloads unlock the Batch API — typically 50% cheaper. Real-time means the user is waiting.
Do your prompts share the same prefix or documents? Repeated content can be cached at ~90% off input cost. One-off prompts get no caching benefit.
How much text goes into each prompt? Large contexts (>32K tokens) make caching critical and may trigger long-context surcharges. Prefer chunking + RAG when possible.
How good must the output be? "Good-enough" uses the cheapest tier; "production" ensures customer-facing quality; "frontier" reserves the most capable (and expensive) models.
Data residency or deployment constraint? EU/US residency narrows eligible providers. Self-host limits to open-weight models you deploy on your own infrastructure.
How consistent is your usage? Steady high-volume workloads may benefit from reserved capacity (PTU). Bursty or low traffic is better served by pay-per-token pricing.

How the Decision Engine Works

The engine walks a deterministic six-rule tree in fixed order. Same inputs always produce the same outputs and the same trace. The philosophy is: cheapest viable, where viability is enforced by tier filters and compliance gates — not by judgment.

Rule 1 — Async or Real-time?

If the workload is asynchronous (hours-OK), the Batch API lever activates — applying a 0.5× multiplier to both input and output tokens. Real-time and near-real-time workloads use standard per-token rates.

Rule 2 — Simple or Complex?

The quality bar and task type together set a tier band [min, max] for eligible models. Two floors apply — the higher one wins:

QualityMin TierMax Tier
Good-enough12
Production23
High34
Frontier44

Task floors: classification/extraction = tier 1, chat/summarization/coding = tier 2, reasoning/agent = tier 3. Reasoning and agent tasks get a +1 buffer so the engine considers one tier above the floor.

Rule 3 — Repeated Context or One-off?

Sets the cache hit rate for models that support prompt caching:

Reuse PatternCache Hit RateEffect
One-off0%Caching disabled
Repeated prefix70%System prompts, few-shot scaffolding
Heavy document reuse90%Same document referenced repeatedly

Cached input is priced at ~10% of base rate. Formula: eff_input = (1 − hit) × base + hit × cached_rate

Rule 4 — Compliance or Residency Need?

Filters the candidate set by data residency or deployment constraint:

  • None — all providers eligible, no premium
  • US residency — filter to US/global providers, +10% premium
  • EU residency — filter to EU-eligible providers only
  • Self-host — filter to open-weight models only (currently Mistral Small 4, Phi-4 mini, Phi-4)

If compliance leaves an empty candidate set, the engine returns an error rather than silently relaxing constraints.

Rule 5 — Bursty or Steady-state?

Steady-state high-volume workloads (>60% utilization) surface a note recommending provisioned capacity (Microsoft Foundry PTU). Cost is not algorithmically adjusted — PTU sizing is workload-dependent.

Rule 6 — Lowest-cost Eligible Model

For every surviving candidate, compute monthly cost with all levers stacked:

monthly = eff_input × vol_in + eff_output × vol_out × effort_factor

Where effort_factor = 0.65 for models with reasoning effort control (when quality ≠ frontier). This reduces output token consumption by ~35%.

Output Structure

The JSON export includes: recommendation (provider, model, effective rates, monthly cost, why-cheaper), baseline comparison (GPT-5.5 real-time), savings (dollars and percent), levers applied (with kind: savings or note), up to 4 alternatives, and the full decision trace.

Baseline Definition

GPT-5.5 real-time, no caching, no batching, no effort tuning: baseline = $5.00 × vol_in + $30.00 × vol_out. Chosen as the frontier-tier reference point that teams most commonly default to.

Invariants

  • Empty candidate set → error (never silently relaxes constraints)
  • Lower tier wins at equal effective rates (monotonicity)
  • Batch reduces both input and output equally
  • Caching applies only to input tokens — output is never cached
  • Effort reduces output volume, not output rate
  • Residency premium multiplies both input and output rates
  • Trace order always matches rule order
  • Savings is always baseline − recommended (never negative-as-positive)

Universal Cost Optimization Strategies

These techniques apply across all AI providers. Applying them in combination produces compound savings.

1. Model Right-Sizing (50–95% savings)

Start with the smallest model that meets quality requirements. Most production workloads do not need frontier-tier models. A practical rule: begin with the cheapest model and only move up if evals or user feedback show a quality gap.

Task ComplexityRecommended TierExample Models
Simple (classification, extraction)Nano / MiniMinistral 3B, Phi-4 mini, GPT-5.4 nano, Flash-Lite
Standard (chat, summarization)Mid-tierMistral Small 4, Phi-4, GPT-5.4 mini
Complex (reasoning, coding)StandardGPT-5.4, Claude Sonnet 4.6, Mistral Large 3
Frontier (research, deep analysis)FlagshipGPT-5.5, Claude Opus 4.8

2. Batch Processing (50% savings)

Use batch for any non-real-time workload. All 5 providers offer ~50% off for batch. This is the easiest lever with zero quality tradeoff — the only cost is latency (typically 24h turnaround).

3. Prompt Caching (75–90% input savings)

Cache repeated prefixes — system prompts, policy documents, few-shot examples. Cached tokens are served at ~10% of base rate. Place static content at the beginning of prompts and keep prefixes identical to maximize hit rates.

4. Reasoning Effort Control (30–70% savings)

Use the lowest reasoning effort that still solves the task. Models with effort parameters (OpenAI, Anthropic) can dramatically reduce hidden thinking tokens. Medium is often the best default — reserve high for genuinely hard cases.

5. Token Optimization (10–30% savings)

Set max_tokens, remove unnecessary boilerplate, prefer structured outputs for machine-consumed responses. Summarize long documents before sending to expensive models.

Provider-Specific Recommendations

Mistral

Pricing: Ministral 3B ($0.10/$0.10), Small 4 ($0.10/$0.30), Large 3 ($0.50/$1.50), Codestral ($0.30/$0.90)

  • Lowest per-token rates in the catalog — dominant cost leader at tiers 1–3
  • No prompt caching support, but base rates are so low caching wouldn't help competitors catch up on output cost
  • Small 4 is open-weight (Apache 2.0) — self-hostable for fixed-cost deployment
  • Codestral is purpose-built for code generation at 3× cheaper output than GPT-5.4 mini
  • Batch API: 50% off, 24h turnaround

OpenAI

Pricing: GPT-5.4 nano ($0.20/$1.25), mini ($0.75/$4.50), GPT-5.4 ($2.50/$15), GPT-5.5 ($5/$30)

  • Automatic prompt caching on GPT-4o+ — no manual setup required
  • Cached input at 10% of base rate (e.g., $0.075/MTok for GPT-5.4 mini)
  • Batch API: 50% off, separate enqueued-token quota
  • reasoning_effort parameter on reasoning-capable models (low/medium/high)
  • Regional residency adds ~10% premium for models released March 2026+

Anthropic (Claude)

Pricing: Haiku 4.5 ($1/$5), Sonnet 4.6 ($3/$15), Opus 4.5–4.8 ($5/$25)

  • Explicit prompt caching with two TTLs: 5-min (write 1.25×, read 0.1×) and 1-hour (write 2×, read 0.1×)
  • Best effort control: low/medium/high/xhigh/max — affects all tokens including tool calls and thinking
  • Opus 4.7+ uses a new tokenizer: up to 35% more tokens for equivalent text — factor into migration cost estimates
  • Especially attractive for agentic workflows with heavy prompt reuse
  • Batch API: 50% off, usually <1 hour turnaround

Google Gemini

Pricing: Flash-Lite 3.5 ($0.25/$1.50) — only model with verified pricing in v0.1

  • Flash-Lite is a strong low-cost option for high-volume simple tasks
  • Context caching: both implicit (auto on 2.5+) and explicit (manual TTL)
  • Four pricing tiers: Standard, Batch (~50% off), Flex (~50% off), Priority (1.8× premium)
  • Flash and Pro models omitted from v0.1 pending verified pricing

Microsoft Foundry

Pricing: Foundry GPT-5.4 mini ($0.75/$4.50), GPT-5.4 ($2.50/$15), Phi-4 mini ($0.075/$0.30), Phi-4 ($0.125/$0.50)

  • OpenAI models available with EU residency (not available on direct OpenAI)
  • Provisioned Throughput (PTU): fixed hourly capacity, cheaper than pay-per-token above ~60–70% utilization. Cached tokens are FREE on PTU.
  • Phi-4 models are Microsoft-native SLMs, open-weight (MIT), and self-hostable
  • Phi-4 mini at $0.075 input — cheapest input rate in the entire catalog
  • Phi-4 at $0.125/$0.50 competes with Mistral Small 4 at $0.10/$0.30 with Azure ecosystem support
  • Model Router: auto-route to optimal model per request for multi-model architectures

Cohere (Excluded from v0.1)

Cohere is positioned as a retrieval and enterprise workflow provider. Its cost play is architectural — use Embed + Rerank to reduce candidates before sending to expensive generation models. Documented as yielding 90%+ reduction in tokens sent to generation. Pending verified 2026 pricing for inclusion.

About This Project

The AI Inference Cost Optimizer is a research-driven project that analyzes how organizations can reduce AI inference costs across major cloud providers. As AI adoption accelerates, inference spending is becoming one of the largest and fastest-growing line items in technology budgets — yet most teams lack systematic tools to compare options and identify savings.

This decision assistant is the interactive component of that research. It distills findings from 500+ pages of provider documentation into a single, transparent tool that helps engineering and FinOps teams make informed model selection decisions.

It is a rule-based router that explains its reasoning — not a calculator, not a benchmark, and not a recommendation engine that guarantees results.

Scope & Model Selection

The dashboard evaluates 16 curated models across 5 providers (Mistral, OpenAI, Anthropic, Google Gemini, Microsoft Foundry). Why 16? It is a deliberately manageable set that covers the models most likely to matter for practical cost comparison, while keeping the rule framework transparent and auditable. The selection prioritizes breadth across price tiers (simple → standard → complex → frontier) over exhaustive catalog coverage.

The model catalog includes:

  • Mistral — 4 models: Ministral 3B, Small 4, Large 3, Codestral
  • OpenAI — 4 models: GPT-5.4 nano, GPT-5.4 mini, GPT-5.4, GPT-5.5
  • Anthropic — 3 models: Claude Haiku 4.5, Claude Sonnet 4.6, Claude Opus 4.8
  • Google Gemini — 1 model: Gemini 3.5 Flash-Lite (only model with verified pricing)
  • Microsoft Foundry — 4 models: Foundry GPT-5.4 mini, Foundry GPT-5.4, Phi-4 mini, Phi-4

Cohere is excluded from v0.1 pending verified 2026 generation pricing. Cohere is better framed as a retrieval/rerank provider — its cost play is architectural (reduce tokens sent to expensive generation models), not per-token.
